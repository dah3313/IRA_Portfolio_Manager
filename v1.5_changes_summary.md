# Post-ratification broker-layer refinements (2026-05-12)

Four refinements driven by a code review of the broker layer
(GemBroker.txt external review + Claude's deeper review of
`broker_protocol.py`, `ibkr_broker.py`, `synthetic_broker.py`, and
`cycle_attempt.py`). All changes are bug-class or robustness fixes
against the as-ratified v1.5 design; no contract changes. Spec
version remains v1.5.

## Code changes

### `ibkr_broker.py`
- `POST_PLACEMENT_CONFIRMATION_WINDOW_SEC`: 5.0 → 15.0 seconds, with
  expanded docstring explaining the asymmetric-cost rationale
  (a false-positive `BrokerInconsistency` is the only halt category
  NOT eligible for 48h auto-resume).
- `connect()` now cross-checks `ib_async.IB.isConnected()` when its
  internal `_connected` flag is True. On disagreement (TWS restart
  or connection drop between cycles), logs stale-flag detection,
  resets the flag, and performs a real reconnect. If `isConnected()`
  itself raises, treats as not-connected and falls through. Aligns
  `connect()`'s view of state with `is_ready()`'s.
- Docstring updated with "IDEMPOTENCY & SELF-HEALING (Change 4)"
  section.

### `broker_protocol.py`
- Four "5 sec" → "15 sec" references updated (BrokerInconsistency
  class docstring, exception-model comment block, `place_order`
  POST-PLACEMENT CONFIRMATION section, `place_order` Raises section).
- `connect()` protocol docstring rewritten: "Idempotent and
  self-healing: calling connect() when already connected is a no-op
  IF the underlying transport is still alive. If the implementation
  detects the transport has been lost since the last successful
  connect, it performs a real reconnect rather than returning early."

### `synthetic_broker.py`
- New module constant `SETTLEMENT_CALENDAR_DAYS = 1` with full
  rationale docstring (calendar-days vs business-days choice, why
  not zero motivation).
- New instance field `_cash_unsettled_since: Optional[datetime]`
  tracks when the current unsettled-cash block began accumulating.
  First SELL of a block sets the timestamp; subsequent SELLs use
  earliest-wins semantics (do not extend the block).
- `_apply_fills_to_account()` records timestamp on SELL fills.
- `evolve_pending_state()` now gates unsettled→settled promotion on
  `≥ SETTLEMENT_CALENDAR_DAYS` elapsed since `_cash_unsettled_since`.
  Backward-compat fallback: if timestamp is None (direct test
  mutation), promote immediately. Clears timestamp on promotion.
- `get_recent_activity()` removed the silent 48h cap on `since`;
  now honors caller's value verbatim, matching the Protocol contract
  and IBKRBroker behavior.
- `ACTIVITY_LOOKBACK_HOURS` docstring corrected to reflect its
  documentary-only role (no longer enforced as an active limit).
- `snapshot()` now includes `cash_unsettled_since` for forensic
  inspection.
- `SETTLEMENT_CALENDAR_DAYS` added to `__all__`.

## Spec changes (IRAPM_SPECIFICATION.md)
- **§11.2.14 Broker inconsistency**: `POST_PLACEMENT_CONFIRMATION_WINDOW_SEC`
  reference updated from "(default 5s)" to "(default 15s)".
- **§15.5 Post-placement confirmation**: paragraph rewritten to
  reference the constant by name (default 15 seconds) instead of
  the hardcoded "5 seconds". Added a sentence explaining the
  asymmetric-cost rationale.
- **§15.3 Per-cycle connection lifecycle**: new "Idempotent and

No changes to the synthetic-broker contract in spec text — the

fixes that bring the synthetic implementation into compliance with

## DECISIONS.md additions

- **D-BROKER-8** SyntheticBroker T+1 settlement aging model
- **D-BROKER-9** SyntheticBroker `get_recent_activity()` honors `since` verbatim

## Policy framing
A cross-cutting policy was established during the review: IRAPM
leans hard toward fail-safe and self-resolving in cases where a
false-positive halt costs more (operator-required clearance) than
a conservative auto-resolve. D-BROKER-7 (wider confirmation window)
and D-BROKER-10 (self-healing connect) both follow this principle
explicitly.
